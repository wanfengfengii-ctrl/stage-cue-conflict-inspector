# 舞台设备资源冲突检视器

灯光、升降台、雾机等各部门的提示（cue）由多人分别编排，单看每张表都合理，
合并后却可能在**同一台设备**上出现危险的时间重叠。本工具是一个**纯前端**
React 检视器：舞台监督把合并后的提示粘贴为 JSON 数组，立即完成资源冲突检视，
并按资源绘制可滚动时间轴；选择冲突时，争用双方与交集时间段同步高亮。

- React 18 + TypeScript + Vite 6
- 单元测试：Vitest
- 端到端测试：Playwright（Chromium）
- 无后端、无网络请求：所有解析与检测均在浏览器本地完成

## 输入约定

输入必须是一个 **JSON 数组**，至少包含一条；每个元素是对象，字段如下：

| 字段      | 类型     | 要求                                                                 |
| --------- | -------- | -------------------------------------------------------------------- |
| `id`      | `string` | 非空，且在整批输入中**唯一**                                         |
| `resource`| `string` | 非空，设备资源名；只有同名资源之间才会检测冲突                       |
| `startMs` | `number` | 整数毫秒，`0 ≤ startMs ≤ 86400000`（一天）                           |
| `endMs`   | `number` | 整数毫秒，`0 ≤ endMs ≤ 86400000`，且 `startMs < endMs`               |

示例：

```json
[
  { "id": "LX-01", "resource": "灯光-面光L1", "startMs": 0, "endMs": 120000 },
  { "id": "LX-02", "resource": "灯光-面光L1", "startMs": 60000, "endMs": 180000 },
  { "id": "FOG-01", "resource": "雾机-上场门", "startMs": 90000, "endMs": 150000 }
]
```

### 冲突判定规则

- 区间一律采用**半开区间 `[startMs, endMs)`**：提示在 `startMs` 时刻开始占用，
  在 `endMs` 时刻释放。
- 仅当两项的 `resource` 相同，**且交集长度严格大于 0** 时构成冲突：
  - 重叠起点 = `max(startA, startB)`
  - 重叠终点 = `min(endA, endB)`
  - 时长 = `重叠终点 − 重叠起点`，必须 `> 0`
- 因此一条的 `endMs` 恰好等于另一条的 `startMs`（贴边交接）**不会被误报**；
  交集哪怕只有 **1ms** 也会被逐毫秒定位出来。
- 不同 `resource` 的提示即使时间段完全重合也不冲突。

### 输出与排序

每一对冲突只输出一次，给出：双方 `id`（按 Unicode 码点顺序分为较小/较大）、
重叠起点、重叠终点、重叠时长（毫秒）。列表按以下键排序：

1. `resource`（Unicode 码点顺序）
2. 重叠起点 `overlapStart`
3. 较小的 id（Unicode 码点顺序）
4. 较大的 id（Unicode 码点顺序）

排序基于码点（code point）而非本地语言排序或 UTF-16 码元，emoji 等
增补平面字符的次序也确定可复现。

### 整批拒绝

出现以下任一情况时，**整批输入被拒绝**，页面在对应条目附近（第 N 条 / 行号，
点击问题徽章可选中该条原文）给出原因，并且**不会保留或沿用任何旧结果**：

- 输入不是 JSON 数组、JSON 语法错误、或数组为空；
- 任一条目缺少字段、字段类型不符、时间超出 `0..86400000`、非整数、
  或 `startMs ≥ endMs`；
- `id` 为空字符串或在批内重复。

## 紧凑时间轴

当全天提示只集中在少数排练片段时，整日等比例会把有效区间挤成一条线，连
1ms 的交集都无法点中。合法结果下可切换**紧凑时间轴**（仅显示模式切换）：

1. 先**合并所有资源**提示的半开占用区间 `[startMs, endMs)`（贴边交接合为一段，
   不产生空档）；
2. 相邻占用之间（含日首、日尾）**严格超过五分钟**的空档，统一映射为
   **固定三十秒显示宽**；
3. 占用区间与不超过五分钟的短空档保持同一等比例（1 真实毫秒 = 1 显示毫秒）。

映射由 `src/core/compactScale.ts` 的 `createTimeScale(mode, items)` 确定性构建，
返回有序且首尾相接的分段（真实毫秒 ↔ 显示坐标双向可换算）：

- 时间轴的提示块、冲突交集、刻度与点击区域**统一消费同一映射**；
  映射只规定相对比例，渲染时整条压缩轴再**等比缩放铺满面板**（紧凑模式无需横向滚动）。
  缩放后物理宽度不足 1px 的 1ms 真实争用由最小点击热区承载，位置仍精确取自映射，
  可逐毫秒点中；
- 交集点击按**点击坐标**在该行全部热区中解析归属，与 DOM 叠放顺序无关：
  多组争用完全重叠时在同一点逐组轮换选择核对，紧凑轴相邻争用扩展热区互相覆盖时
  选中的仍是用户指向的那一组；
- 被压缩空档处绘制**断轴标记**（双斜杆），并在刻度带标注该空档的
  **真实起止与真实时长**；刻度真实时刻由映射反演，压缩空档内部不画刻度；
- 冲突列表继续消费原有 `Conflict` 与 `selectedKey`——列表选择与时间轴高亮
  始终指向同一争用；
- 紧凑模式**只压缩显示**：不改写提示、不改变冲突排序与半开区间判定。

模式约束：

- App 只保存 `day`（整日）/ `compact`（紧凑）两种显示模式，映射纯派生；
- **切回整日后仍有效的冲突选择原样保留**；
- **编辑 JSON（载入示例/粘贴/修改）即恢复整日模式**并走原有整批校验；
- 非法输入仍整批拒绝，列表与时间轴（含模式开关）一并撤下，不沿用旧结果。

## 聚焦上下文

定位到某次设备争用后，舞台监督常需要暂时收窄时间轴，核对冲突前后各三十秒内的
上下游提示，再回到完整演出继续核对。选中任一争用后可执行**聚焦上下文**：

1. 以该争用的**交集起止**为锚，向两侧各扩 **30 秒**，并夹到当天 `[0, 86400000]`
   范围内（日界处不再外扩，不会出现负毫秒）；窗口由 `src/core/focusWindow.ts`
   的纯函数 `createFocusWindow` 确定性给出；
2. 窗口仍是**半开区间 `[startMs, endMs)`**，窗口内只呈现**与其相交**的提示与冲突——
   恰好贴边（一项 `endMs` 等于窗口起点，或 `startMs` 等于窗口终点）不算相交；
3. **跨边界图形可裁短**（几何在窗口边缘截断），但提示的标签、冲突排序与所有
   **绝对毫秒值保持原样**（title/卡片仍显示真实起止，不做相对化改写）；
4. 退出聚焦后回到完整演出，**冲突列表始终使用原有 `Conflict` 对象与稳定
   `conflictKey` 选择身份**，选中项原样保留。

`createTimeScale(mode, items, window?)` 增加可选窗口参数：给定后映射只覆盖该区间，
窗口内整日等比例 / 紧凑压缩规则不变（窗口内超过五分钟的空档仍压成三十秒显示宽）。
因此：

- 聚焦期间切换整日 / 紧凑**只重算坐标**，窗口与选中项均不改变；
- 聚焦期间完全重叠的多组争用仍可在同一点逐组轮换选择；
- 若在冲突列表选中一个**窗口外**的争用（选择在当前窗口内失效），给出就近反馈、
  **退出聚焦**并在完整演出中定位该争用；
- **编辑、粘贴或载入示例会清除聚焦并恢复整日模式**；非法输入仍撤下全部结果。

## 资源范围隔离

设备提示较多时，舞台监督可以先**隔离某一项资源**，核对该资源的全部占用与争用，
再恢复全场视图继续排查：

1. 从**时间轴资源名称**（每行左侧的资源名按钮）或工具栏的**资源范围**下拉选择范围；
   通过**“显示全部资源”**按钮（或下拉中的“全部资源”）返回全场视图；
2. 范围只对已通过校验的 `CueItem` 与既有 `Conflict` 建立**确定性可见投影**
   （`src/core/resourceScope.ts` 的纯函数 `projectItems` / `projectConflicts`），
   **列表与时间轴消费同一份投影**——排序、绝对时刻、半开区间判定与冲突选择身份
   （`conflictKey`）均不改写，投影内外都是同一批对象；
3. App 只保存“全部资源（`null`）/ 指定资源（资源名）”这一组范围状态；
   切换范围时，**选中的争用不属于新范围便同步取消**（聚焦锚点同理随之退出），
   属于该范围（或回到全部资源）则原样保留；
4. 整日、紧凑、聚焦与时刻游标仍按现有坐标及窗口规则工作——它们消费的
   就是投影后的结果（如时刻游标的占用清单只列范围内资源）；
5. **编辑、粘贴、载入示例或输入转为非法时恢复全部资源**；非法输入仍整批拒绝、
   撤下全部结果；
6. 若隔离的资源**没有争用**，页面明确说明“该资源无争用”（局部结论），
   **不会**宣告整批可执行——其余资源的争用需回到全场视图核对。

## 本地开发

```bash
npm install
npm run dev        # 启动 Vite 开发服务器（默认 http://localhost:5173）
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 本地预览生产构建
```

## 测试

```bash
npm run test       # Vitest 单元测试（校验、冲突检测、码点排序、JSON 定位）
npx playwright install chromium   # 首次运行端到端测试前安装浏览器
npm run e2e        # Playwright 端到端（自动起 dev server）
npm run acceptance # 完整本地验收：build + Vitest + Playwright
```

## Docker 发布与验收

```bash
# 构建并发布（默认宿主机端口 8080）
docker compose up --build
# 自定义发布端口：
WEB_PORT=9000 docker compose up --build
```

`WEB_PORT` 仅改变宿主机发布端口（容器内固定监听 8080），例如
`WEB_PORT=9000` 后访问 http://localhost:9000 。

一次性验收服务 `verify` 会在容器内执行 **生产构建 → Vitest → Playwright**，
全部通过则退出码为 0：

```bash
docker compose build verify
docker compose run --rm verify
```

```
src/
  core/            # 纯逻辑：类型、校验、冲突检测、格式化、JSON 文本定位、
                   #        compactScale（整日/紧凑/聚焦窗口分段映射）、conflictKey（无碰撞选择身份）、
                   #        overlapHit（交集热区坐标命中解析）、focusWindow（前后各三十秒聚焦窗口、
                   #        半开相交与裁切）、momentCursor（时刻游标反演与占用判定）、
                   #        resourceScope（资源范围投影与选择同步判定）（均含单测）
  components/      # InputPanel / Timeline / ConflictList / MomentDetails
  App.tsx          # 粘贴即检测；非法输入整批拒绝、不沿用旧结果；
                   # 编辑 JSON 恢复整日模式、清除聚焦并恢复全部资源范围
  App.test.tsx     # React 交互测试（jsdom）：聚焦主链路、叠放争用逐组轮换、选择失效退焦、
                   # 时刻游标链路、资源范围隔离主链路
e2e/               # Playwright 端到端测试（含紧凑模式切换、1ms 压缩交集、断轴、聚焦上下文、
                   # 时刻游标与资源范围隔离主链路）
Dockerfile         # web（静态发布）与 verify（一次性验收）两个目标
docker-compose.yml # web（WEB_PORT 可覆盖）+ verify
```
